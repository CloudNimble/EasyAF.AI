## Summary

The McpEssentials task store: SDK [IMcpTaskStore](/mcpessentials/api-reference/ModelContextProtocol/Extensions/Tasks/IMcpTaskStore) plus owner binding, TTL, and sweep.

## Remarks

SEP-2663 binds each task to an authorization context. This interface is that store.
The SDK calls the [IMcpTaskStore](/mcpessentials/api-reference/ModelContextProtocol/Extensions/Tasks/IMcpTaskStore) methods, which have no user parameter;
implementations resolve the owner from the callback captured at construction.
Hosts that already have a [ClaimsPrincipal](https://learn.microsoft.com/dotnet/api/system.security.claims.claimsprincipal) call the overloads directly.

Client-facing operations (create, get, cancel, resolve) require an owner and treat
another caller's task as missing. Server-side completion skips the live-owner check
because the SDK runs those from a background DI scope after the originating request is gone.

### <Icon icon="function" iconType="duotone" color="#419AC5" size={24} className="mr-2" /> SweepExpiredAsync <Badge color="orange">Abstract</Badge>

Removes snapshots the store's discard criteria say are gone.

#### Syntax

```csharp
System.Threading.Tasks.Task SweepExpiredAsync(System.Threading.CancellationToken cancellationToken = null)
```

#### Parameters

| Name | Type | Description |
|------|------|-------------|
| `cancellationToken` | `System.Threading.CancellationToken` | Cancellation token for the operation. |

#### Returns

Type: `System.Threading.Tasks.Task`
A task that completes when the pass finishes.

#### Exceptions

| Exception | Description |
|-----------|-------------|
| `OperationCanceledException` | *cancellationToken* was cancelled during the pass. |

#### Remarks

Always runs a full pass. Automatic create/get pulses are separate and throttled.
Set `AutoSweep` to [`false`](https://learn.microsoft.com/dotnet/csharp/language-reference/builtin-types/bool) and call this method from your own job
when you want to own the schedule.

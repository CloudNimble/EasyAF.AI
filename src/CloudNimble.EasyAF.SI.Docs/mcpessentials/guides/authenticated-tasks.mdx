MCP Tasks (SEP-2663) let a client start long-running work, get a task id, and poll `tasks/get` until the work finishes. The C# SDK stores that state in `IMcpTaskStore`. The built-in `InMemoryMcpTaskStore` is shared across every request to the process.

[`InMemoryMcpTaskStorePlus`](/mcpessentials/api-reference/CloudNimble/McpEssentials/Core/Tasks/InMemoryMcpTaskStorePlus) records the owner on create and never leaks another user's task, payload, or existence. Durable providers persist the same contract.

<CardGroup cols={3}>
  <Card title="Stamp the owner" icon="user">
    `CreateTaskAsync` reads the current user and records it on the snapshot.
  </Card>
  <Card title="Isolate later calls" icon="lock">
    Get, cancel, and resolve require that user. Anyone else sees not found.
  </Card>
  <Card title="Complete in the background" icon="gears">
    The SDK finishes work after the HTTP request is gone. Complete, fail, and set-input skip the live-user check.
  </Card>
</CardGroup>

## Wire it up

HTTP hosts register `IHttpContextAccessor` the platform way and pass a factory that resolves it from the built `IServiceProvider`.

<Tabs>
  <Tab title="HTTP" icon="globe">
    ```csharp
    builder.Services.AddHttpContextAccessor();

    builder.Services.AddMcpServer()
        .WithHttpTransport(o => o.Stateless = true)
        .WithTools<MyTools>()
        .WithTasksPlus(
            sp => sp.GetRequiredService<IHttpContextAccessor>().HttpContext?.User,
            o => o.DefaultTimeToLive = TimeSpan.FromMinutes(5));
    ```

    The SDK `WithTasks` API needs the store object at registration time, before `Build()`. The factory overload creates the store immediately and captures the provider when the container is built. Each client-facing task call then reads `HttpContext.User`.
  </Tab>
  <Tab title="Stdio" icon="terminal">
    ```csharp
    builder.Services.AddMcpServer()
        .WithTasksPlus("local-user");
    ```
  </Tab>
  <Tab title="Store only" icon="database">
    Same factory, without `IMcpServerBuilder`:

    ```csharp
    builder.Services.AddHttpContextAccessor();
    builder.Services.AddInMemoryMcpTaskStorePlus(
        sp => sp.GetRequiredService<IHttpContextAccessor>().HttpContext?.User,
        o => o.DefaultTimeToLive = TimeSpan.FromMinutes(5));
    ```
  </Tab>
  <Tab title="Tests" icon="flask">
    ```csharp
    IMcpTaskStorePlus store = new InMemoryMcpTaskStorePlus("user-1");

    var store2 = new InMemoryMcpTaskStorePlus(() => currentUserId);

    var created = await store2.CreateTaskAsync(httpContext.User);

    builder.WithTasksPlus(sp => sp.GetRequiredService<ClaimsPrincipal>());
    ```
  </Tab>
</Tabs>

<Tip>
Async `[McpServerTool]` methods that return `Task` / `Task<T>` automatically advertise task support. A client that opts into `io.modelcontextprotocol/tasks` gets a task id owned by the user on that request.
</Tip>

No user on a client-facing call throws [`McpTaskUserRequiredException`](/mcpessentials/api-reference/CloudNimble/McpEssentials/Core/Tasks/McpTaskUserRequiredException).

## Overloads

| Call | When |
|---|---|
| `WithTasksPlus("user-id")` | Stdio, tests, one user for the process |
| `WithTasksPlus(() => currentUserId)` | Tests that switch the user id |
| `WithTasksPlus(() => principal)` | A principal you already hold |
| `WithTasksPlus(sp => sp.GetRequiredService<IHttpContextAccessor>().HttpContext?.User)` | ASP.NET Core. Call `AddHttpContextAccessor()` first. |

Each overload has a matching `AddInMemoryMcpTaskStorePlus` on `IServiceCollection`. Pass `McpTaskStoreOptions` as the next argument to set `DefaultTimeToLive` and `DefaultPollIntervalMs`. `null` TTL keeps tasks until the store discards them.

Claim lookup matches the SDK session identity order: `NameIdentifier`, `sub`, `UPN`, `Name`. Types are unsealed; subclass [`McpTaskStoreBase`](/mcpessentials/api-reference/CloudNimble/McpEssentials/Core/Tasks/McpTaskStoreBase) to change isolation, TTL, or storage.

## Isolation rules

| Operation | Current user required | Other user's task |
|---|---|---|
| `CreateTaskAsync` | Yes (throws) | n/a |
| `GetTaskAsync` | Yes (throws) | `null` |
| `SetCancelledAsync` | Yes (throws) | `false` |
| `ResolveInputRequestsAsync` | Yes (throws) | no-op, no event |
| `SetCompletedAsync` | No | allowed (server-side) |
| `SetFailedAsync` | No | allowed (server-side) |
| `SetInputRequestsAsync` | No | allowed (server-side) |

Owner comparison is ordinal. Register the store as a **singleton**. Stateless HTTP creates a fresh `McpServer` per POST; a scoped store looks empty on the next `tasks/get`.

<Warning>
Do not store MCP task rows on domain tables. Tasks expire in minutes; orders and users do not.
</Warning>

## Samples

Each sample is a standalone Streamable HTTP host. Fake authentication is the `X-User-Id` header. One tool, `HelloWorld`, injects `ClaimsPrincipal` and returns `Task<string>` so a task-capable client gets a trackable task. The store is the only thing that changes.

<Tabs>
  <Tab title="Basic" icon="memory">
    In-memory. No extra infrastructure.

    ```bash
    dotnet run --project samples/CloudNimble.McpEssentials.Samples.Basic -f net11.0
    ```

    Point a harness at `http://localhost:5280/` with `X-User-Id: alice`. Call `HelloWorld` with the Tasks extension, then `tasks/get` as `alice` and as `bob`. Bob sees not found.

    [`samples/…Samples.Basic`](https://github.com/CloudNimble/McpEssentials/tree/main/samples/CloudNimble.McpEssentials.Samples.Basic)
  </Tab>
  <Tab title="Entity Framework Core" icon="table">
    SQLite file next to the app. Swap `UseSqlite` for any EF provider in a real host.

    ```bash
    dotnet run --project samples/CloudNimble.McpEssentials.Samples.EntityFrameworkCore -f net11.0
    ```

    MCP is at `http://localhost:5290/`.

    [`samples/…Samples.EntityFrameworkCore`](https://github.com/CloudNimble/McpEssentials/tree/main/samples/CloudNimble.McpEssentials.Samples.EntityFrameworkCore)
  </Tab>
  <Tab title="Redis" icon="bolt">

    dotnet run --project samples/CloudNimble.McpEssentials.Samples.Redis -f net11.0

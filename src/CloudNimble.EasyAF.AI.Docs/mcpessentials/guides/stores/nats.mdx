Edge / IoT / already-on-NATS hosts. JetStream Key/Value holds the canonical record. Core NATS subject `mcp.essentials.task.input` wakes waiting `ElicitAsync` callers.

## When to use it

The host already runs NATS and wants KV plus a native subject instead of a database plus a separate bus.

## Intended how-to

1. Add `McpEssentials.Nats` and a NATS connection.
2. Put each `StoredMcpTask` in a JetStream KV bucket keyed by task id, including `OwnerUserId`.
3. Register the store as a singleton with the same current-user factory as [Authenticated tasks](/mcpessentials/guides/authenticated-tasks).
4. After a successful resolve, publish task id plus request id on `mcp.essentials.task.input`. Subscribers raise `InputResponseReceived`.

## TTL

KV entry TTL from `DiscardAfter` (`CreatedAt + 2×TimeToLive`).

See [Stores](/mcpessentials/guides/stores).

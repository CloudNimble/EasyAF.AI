<Warning>
`McpEssentials.DistributedCache` is specified and is not in this repository yet.
</Warning>

Use this when the host already registered `IDistributedCache` (Redis, NCache, SQL Server cache, FusionCache, …) and you want tasks on that abstraction.

<CardGroup cols={2}>
  <Card title="When it ships" icon="circle-check">
    The cache abstraction is already in DI and a host-supplied bus covers fan-out.
  </Card>
  <Card title="Until then" icon="bolt" href="/mcpessentials/guides/stores/redis">
    Prefer Redis when the cache is Redis and you need pub/sub for elicitation.
  </Card>
</CardGroup>

## Intended how-to

<Steps>
  <Step title="Add the package">
    Add `McpEssentials.DistributedCache`.
  </Step>
  <Step title="Key the snapshot">
    Serialize the canonical `StoredMcpTask` record with source-generated JSON. Key `mcp:task:{taskId}`.
  </Step>
  <Step title="Register the store">
    Singleton, same current-user factory as [Authenticated tasks](/mcpessentials/guides/authenticated-tasks).
  </Step>
  <Step title="Optional bus">
    `IDistributedCache` has no pub/sub. For multi-node `ElicitAsync`, register [`IMcpTaskInputSignalBus`](/mcpessentials/api-reference/CloudNimble/McpEssentials/Core/Tasks/IMcpTaskInputSignalBus). Single-node hosts can skip the bus.
  </Step>
</Steps>

## TTL

Set cache entry expiry from `DiscardAfter` (`CreatedAt + 2×TimeToLive`). A missing key is not found.

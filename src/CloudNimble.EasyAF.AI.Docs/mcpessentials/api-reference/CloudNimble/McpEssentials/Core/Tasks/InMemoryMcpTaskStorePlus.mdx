## Summary

An in-memory [IMcpTaskStorePlus](/mcpessentials/api-reference/CloudNimble/McpEssentials/Core/Tasks/IMcpTaskStorePlus) that records the user who created each task
and isolates later client-facing operations to that user.

## Remarks

Storage is owned by this type: [StoredMcpTask](/mcpessentials/api-reference/CloudNimble/McpEssentials/Core/Tasks/StoredMcpTask) snapshots in a
[ConcurrentDictionary`2](https://learn.microsoft.com/dotnet/api/system.collections.concurrent.concurrentdictionary-2), compare-and-swap updates, two-window TTL,
serve-and-drop on a terminal get, plus a throttled sweep. It does not wrap the SDK
`InMemoryMcpTaskStore`.

Tasks created with a [McpTaskStoreBase.DefaultTimeToLive](/mcpessentials/api-reference/CloudNimble/McpEssentials/Core/Tasks/McpTaskStoreBase#defaulttimetolive) use two
clocks (as permitted by SEP-2663): a work window of `CreatedAt + TimeToLive` during which
input and progress are accepted, and a tracking window that keeps the snapshot visible until
`CreatedAt + 2×TimeToLive` so a late complete, fail, or cancel can still be recorded and
polled. That ceiling is stamped as [StoredMcpTask.DiscardAfter](/mcpessentials/api-reference/CloudNimble/McpEssentials/Core/Tasks/StoredMcpTask#discardafter) at write time.
An owner `GetTaskAsync` of a terminal snapshot serves it and then drops the row. An
opportunistic throttled sweep reclaims snapshots nobody collected. Tasks created without a
time-to-live are retained until a terminal get by the owner or until the process exits.

Client-facing operations require a current user and treat another user's task as missing.
Another user's get does not serve-and-drop the owner's row. Server-side completion skips the
live-user check because the SDK runs those from a background DI scope after the originating
HTTP request is gone.

Single-process only. Register as a singleton. Subclass to change isolation, storage, or TTL.
For multi-instance hosts, use a durable provider described in the authenticated task store spec.

#### Syntax

```csharp
public virtual System.Nullable<System.TimeSpan> DefaultTimeToLive { get; set; }
```

#### Property Value

Type: `System.Nullable<System.TimeSpan>`

#### Remarks

When set to a positive value, the work window ends at `CreatedAt + TimeToLive` and
the row is discarded at `CreatedAt + 2×TimeToLive` (stamped as
[StoredMcpTask.DiscardAfter](/mcpessentials/api-reference/CloudNimble/McpEssentials/Core/Tasks/StoredMcpTask#discardafter)), or sooner when a terminal
`GetTaskAsync` serves it. A [`null`](https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/null) or non-positive value keeps tasks
until a terminal get or until the store discards them.
